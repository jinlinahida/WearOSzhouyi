# 六爻装卦规则口径

## 已采用规则

- 输入顺序固定为初爻到上爻；6=老阴、7=少阳、8=少阴、9=老阳。
- 八宫、寻世、认宫参考 `bopo/najia` 固定提交 `9cf119169d7eb8e48febc05274aebf3f7106d647`，覆盖八纯、一至五世、游魂、归魂。
- 纳甲采用京房纳甲表：内卦配置初至三爻，外卦配置四至上爻。
- 六亲以卦宫五行为“我”，按卦宫与爻支五行的生克关系计算。
- 变卦按变卦自己的八宫归属重新计算六亲。这是本项目已确认规则，不沿用上游当前源码把本卦宫传给变卦的行为。
- 六神按日干确定初爻起点，再按青龙、朱雀、勾陈、螣蛇、白虎、玄武循环排到上爻：
  - 甲乙日起青龙
  - 丙丁日起朱雀
  - 戊日起勾陈
  - 己日起螣蛇
  - 庚辛日起白虎
  - 壬癸日起玄武
- 旬空由日柱所在甲子旬计算两个空亡地支；纳支属于其中之一的爻标记为空亡。

## 与参考项目的差异

`bopo/najia` 的公共 `compile` 同时混用传统 6/7/8/9 与内部 1/2/3/4 编码，导致变卦和动爻判断不一致。本项目不移植这段编码逻辑，而是先把四态输入转为明确的阴阳/动静，再推导本卦和变卦。

参考项目当前 `_transform` 用本卦宫计算变卦六亲；本项目遵照产品确认口径，先重新确定变卦宫，再计算变卦六亲。

## 已封装的数据边界

- `GanzhiCalendar`：四柱算法使用 `SixTailGanzhiCalendar` 适配
  `6tail/lunar-java` 的公开 API。设备公历时间先转换为 Solar、Lunar，再生成
  `DivinationTimeInfo` 中的农历显示和四柱；采用精确节气交接时刻、设备时区和晚子时日柱算明天；
  暂不考虑真太阳时或地理修正。测试仍通过接口注入固定四柱，保证装卦规则可以独立验证。
- `LineTextRepository`：爻辞与算法、UI 分离。`JsonLineTextRepository` 从
  `engine/src/main/assets/yao_text.json` 读取已固定修订号的 64×6 数据；当资源缺失、
  JSON 损坏或校验失败时，应用降级为 `EmptyLineTextRepository`，UI 显示“爻辞数据不可用”，不伪造文本。
  数据来源和 CC BY-SA 4.0 归属见 `docs/research/yao-text-data-source.md`。
